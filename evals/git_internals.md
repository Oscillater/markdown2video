# Git 内部原理：一次 commit 背后发生了什么

你每天都在敲 `git commit`。但回车按下去的那一刻，Git 到底做了什么？

## 一切皆是对象

Git 的仓库，本质上是一个对象数据库。它只有三种核心对象。

- blob：只存文件的内容
- tree：存目录结构和文件名
- commit：把一次快照打包，记下作者和时间

## 提交链成历史

每个 commit 都记着上一个 commit 的编号。这个编号叫哈希，是内容的指纹。

我们看一眼真实的仓库：

```bash
git log --oneline
git show HEAD
```

一条链就这么长出来了，这就是你的提交历史。

## 分支只是个指针

所谓分支，其实只是一个 41 字节的文件。里面只有一行字：它指向哪个 commit。

```
ref: refs/heads/main
```

创建一个新分支，就是放进一张新纸条，不到一毫秒。

## 结尾

所以，commit 不是改动的集合，而是一个带指针的快照。

理解了这一点，rebase 和 reset 就都不神秘了。
