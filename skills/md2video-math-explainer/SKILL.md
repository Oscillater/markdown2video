# 数学直觉与连续画布

目标：让观众看出“一个量如何产生另一个量”，而不是把公式做成带朗读的幻灯片。视觉应能支持数学结论，不能只有数学氛围。

## 开始前：先做能力匹配

- 相对链接以本 skill 目录解析。先读 [Plan 契约](../md2video/references/plan.md) 和 [组件参考](../md2video/references/components.md)；执行前读 [运行参考](../md2video/references/runtime.md)。
- 明确题目、受众基础、需要讲清的一个结论，以及用户是否授权制作成片。
- 当前 `math_canvas` 实际支持单位圆、动点和 `sine` / `cosine` 图层。它**不是任意函数绘图、几何作图、LaTeX 推导或通用证明引擎**。
- 其他题目可以在用户接受时使用已提供的精确图片/图示；若素材和组件不足，给出分镜草案及能力缺口，先取得补素材/开发组件的授权，不把题目强行改成三角函数。
- 示例：[单位圆 Plan](examples/unit-circle.plan.json)。复制后再改。它演示同一画布跨 Shot 累积、切到别的画面后再回来；不含外部 BGM 依赖。

## 一、以关系而非公式组织内容

1. **问题**：先问一个观众可理解的问题，例如“圆上一个点的高度，为什么会成为波？”
2. **对象与约定**：建立圆、点、方向、坐标等必要约定；先明确看什么，再让对象运动。
3. **一个变量**：每次只改变/观察一个量，旁白明确指向当前画面对象。
4. **关系的生成**：让投影/曲线随运动出现，而不是先给完成图，再声称观众看到了推导。
5. **回扣与边界**：用刚才的关系回答问题，区分视觉直觉与严格证明，不能用氛围画面充当数学论证。

朗读 Segment 保持一个观察动作或一个判断。重点关系可以留在同一视觉状态中跨多句解释，不要因分句而切断画布。

## 二、单位圆画布的编排方法

- 使用 `math_canvas@1.5.1`，主体为 Scene 挂载，不是每个 Shot 重新开始。
- 同一图示的访问使用**同一 Scene id**；允许在 `scenes` 数组中复现这个 id。若中间切去别的 Scene，回来时画布保留此前图层。
- 同一 Scene id 的 `component`、`render_backend`、`visual_type` 和 `visual_params` 保持一致。只让各次访问的 Shot/上下文变化。
- `visual_params.layers` 明确写出图层的 `kind` 与起笔 `shot`，完整声明在每次访问中一致，不靠文本关键词猜图层。
- 圆和动点由组件提供；合法波层只有 `sine`、`cosine`。锚点必须是这个画布中的真实 Shot id，层按发生顺序编排。
- 若曲线应从小节标题旁白开始，就让 header Shot 属于该画布，并把它设为锚点；不要到后面的正文才起笔。
- 当前动画是一章一圈：一个波层从自己的锚点开始，到下一波层锚点或画布末尾完成；**不是每句/每 Shot 都转一圈**。切走时冻结活跃进度，回到画布后续转。
- 标题卡放在独立 Scene，不放进数学画布。

不要给 Plan 手算角速度、秒数或关键帧。先按解释关系写锚点，用真实配音执行后检查同步；若用户要求的运动无法由现有调度表达，报告限制。

## 三、执行与数学讲解验收

按公共运行流程执行，启用 `--subtitles`。数学画布不显示 Segment 原文，因此通常仍需要旁白字幕。

- [ ] 对象、方向、正负和投影关系没有讲反；字幕用词与实际画面一致。
- [ ] 正弦/余弦在声明的锚点起笔，旁白没有在画面尚未出现时说“已经画完”。
- [ ] 曲线生成过程可见；回到同一画布时，历史图层仍在，没有意外重置。
- [ ] 圆、点、投影、当前曲线与历史曲线有主次，章节牌和字幕没有遮住关键对象。
- [ ] 在锚点附近、章节中段、切回画布后分别抽帧；静态抽帧不能证明运动连贯，必要时要求人工看完整段。
- [ ] 未把示意图当严格证明，未把未支持的公式/函数名称写进组件参数冒充能力。

交付时区分：代码/时间线已验证的事实、画面已检查的内容，以及还需人工观看/试听的部分。
